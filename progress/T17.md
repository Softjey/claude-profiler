**Verify command:** `pnpm verify` (build + full suite) → 38 files, 309 tests, all green.
Plus `buildProfile` over every local transcript → **767/767 profiled, 0 failures**, with
per-profile re-assertion of the five-bucket sum and of the invariant that an `unsplit`
sidecar never carries a split figure and a `split` one never withholds it.

**Honest caveat on the headline number.** No real v2 sidecar exists yet — the hooks are
not installed on this machine, so all 12 real sidecars are v1. The resume/idle correction
was therefore driven end-to-end by a **simulated** v2 sidecar generated for the real
`7a5482ad` transcript, using payload shapes read out of the CC 2.1.274 binary (the Zod
schemas for each hook event). The transcript, its 5732-minute gap and the resulting bucket
arithmetic are real; the `SessionStart` record that names the gap was synthesised. The
first real-session confirmation has to wait for an actual install, and that install is the
user's call, not this task's.

**Overhead, measured rather than assumed.** One invocation of the built script costs
33/35/39/48ms (min/p50/p90/max, n=25) on an M-series Mac. That matches the 26–33ms floor
present in every pre-existing v1 sidecar from sessions running `defaultMode: auto`, where
nothing could have been approved by hand — which is the evidence that the shipped
`approvalMs` was mostly measuring the profiler itself. The figure is now surfaced to the
user as `overheadMs` rather than hidden inside approval.

**T9's open question, resolved.** T9 asked whether `PreToolUse` fires before or after the
permission prompt, and specified that if it fires *before*, `approvalMs` must be dropped
rather than shipped as a guess. It does fire before — its return value may carry a
`permissionDecision`, so it has to. T9's reasoning was right; its remedy was too narrow,
because it assumed the two-event subscription was all that was available. `PermissionRequest`
marks the prompt itself, which makes the split exact instead of impossible, so `approvalMs`
is kept and narrowed to mean only the decision. plan.md's open-questions section is updated
in place. T8's subagent-matching question is also noted there as sidestepped for
hook-profiled sessions (`SubagentStart`/`Stop` carry the id and transcript path outright),
while the time-containment heuristic still governs the ~97% of sessions without hooks.

**Convention check.** `src/hooks/` and `src/metrics/` match their designated slots and the
one-directional dependency rule holds: `trace.ts`/`records.ts` import nothing above
`hooks/`, `hook-insights.ts` and `session-phases.ts` read only from `hooks/` and `metrics/`,
and the TUI is the only layer reaching into `artifact`. Naming: every duration ends in `Ms`,
every timestamp ends in `At` and is ISO 8601 (`recordedAt`, `resumedAt`, `firstFlushAt`),
files kebab-case, types PascalCase. Parse leniency is honored — `readSidecar` still skips a
malformed line, and the hook script swallows a malformed payload. The honesty rule is the
whole point of the task: `approvalPrecision` exists so no label can call an unsplit number
a decision, and `phases` is `null` rather than a zeroed row when nothing was measured.

**A bug fixed on the way.** `installHooks` overwrote its own backup on a second run, so
upgrading a narrower install captured settings that already contained this tool's hooks —
`uninstall-hooks` would then "restore" the user to a half-installed state instead of the
original file. It now keeps the first backup. Covered by "keeps the first backup when a
later run widens the subscription".

**Baseline:** `pnpm verify` green before and after. Schema bumped `0.1` → `0.2` for the two
new top-level fields, with SPEC, README and the six TUI fixtures updated in step.

Notes:

- **Scope was widened deliberately, and it is worth flagging.** The audit that produced this
  task found 31 hook events where the shipped install used 2. This task subscribes to 20 and
  leaves `MessageDisplay` behind `--stream-timing`, because it fires per streaming flush
  rather than per turn and buys only time-to-first-token.
- **Cost (D7) is untouched.** `cacheWaste` is the one USD figure not gated on `cost-state`,
  because CC computes `estimated_cache_write_usd` itself for a resume and a model switch. No
  price table was added and nothing is derived from token counts, so the D7 tradeoff stands
  exactly as the user left it. The `pricing` mode CC used is carried through and displayed.
- **Known merge overlap.** A concurrent session in the main worktree is building
  `model-breakdown.ts` (splitting the Model bucket from the transcript side: block kinds,
  `isFirstOfRequest`, `effort`, API-error records). This task deliberately did not build a
  competing Model breakdown; its `MessageDisplay` work measures time-to-first-token, which
  the transcript cannot express. Both touch `src/artifact/profile.ts`, `src/artifact/schema.ts`
  and the TUI fixtures, so conflicts are expected there — one-line ones in the fixtures
  (`schemaVersion` plus the two new fields).
