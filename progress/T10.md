Notes:

- **T9's verdict drove the design directly.** T9 established `approvalMs` is isolatable and that `tool_use_id` correlates hook events to transcript entries exactly, so T10 does not narrow scope (per T9's own note) — both `exactMs` and `approvalMs` are computed and kept, per call: `exactMs = PostToolUse.durationMs`, `approvalMs = max(0, (PostToolUse.at - PreToolUse.at) - exactMs)`.
- **T9 also found that hook config loads once at session launch.** `install.ts`'s docstring/design assumes this: it only has to land in `settings.json` before the *next* session starts, and makes no attempt to affect the current one.
- **Partial hook coverage is never guessed at.** If only some of a tool's calls have a matched `PreToolUse`/`PostToolUse` pair (e.g. hooks were installed mid-session), that tool's `exactMs`/`approvalMs` are the sum over matched calls only — never inferred for the unmatched remainder. A tool with zero matched calls gets `null`/`null`, not `0`. `precision` flips to `"exact"` only once at least one call anywhere was actually matched, so a stale/empty sidecar file leaves the profile exactly as derived.
- **Types outside T10's Files list were not modified.** `ToolStat` (`tool-stats.ts`, T6) and `TimeSplit` (`time-split.ts`, T5) are both owned by earlier tasks and were left untouched. `sidecar.ts` instead defines its own local, additive types — `ExactToolStat = ToolStat & { exactMs, approvalMs }` and `MergedTimeSplit = Omit<TimeSplit, "precision"> & { precision: "derived" | "exact" }` — so the literal `"derived"` type T5 shipped never needs widening at its source; only `mergeSidecar`'s own return type carries the union.
- **No CLI wiring.** `install-hooks`/`uninstall-hooks` (SPEC F3) aren't exposed as subcommands anywhere — `src/cli/index.ts` is outside this task's Files list (`src/hooks/*` only) and has no subcommand dispatch to hang onto yet. `installHooks()`/`uninstallHooks()` are exported, fully testable library functions; wiring them into `bin.ts`/`index.ts` is left for whichever task extends the CLI's argument parsing (not currently an explicit task in `plan.md`).
- The backup format (`{ existed: boolean, raw: string }` at `~/.claude/profiler/hooks-install-backup.json`) is what makes uninstall byte-identical unconditionally, including the edge case where `settings.json` didn't exist before install (uninstall then deletes it rather than writing an empty file) — covered by `uninstall.test.ts`.
