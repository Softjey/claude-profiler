### Convention check
- Layer direction: `Timeline.tsx`/`Context.tsx` import only `artifact` (`Profile`), `metrics/
  tool-stats.js` (`ToolCall`), `metrics/context.js` (`ContextPoint`) — all "lower" than `tui` —
  plus `shell.ts` and `format.ts`. `Sparkline.tsx` imports only `ink`. No import from `cli`.
- Naming: `kebab-case.tsx` files, `PascalCase` components, `camelCase` functions; every duration
  field ends in `Ms` (`toolsMs`, `startMs`); `formatCount` (added to `format.ts`) is not a
  duration/timestamp field so the `Ms`/`At` suffix rules don't apply to it.
- Honesty rule: the "Span" column and `TurnDetailScreen` never call the wall-clock gap between
  turns a processing duration; `buildTurnRows`'s doc comment and the Notes below spell out
  exactly what's derived vs. genuinely absent from the artifact.
- Tests: Vitest + `ink-testing-library`, matching T13/T14's pattern.

Notes (deviations / things worth knowing):
- **Two of plan.md's five listed Timeline columns are not obtainable from the Profile artifact as
  it exists today**, and this task's Files list (`Timeline.tsx`, `Context.tsx`, `Sparkline.tsx`
  only) doesn't include the metrics/artifact layer that would be needed to add them. SPEC.md's
  own FR list (FR17) and D11 ("5 v1 metrics": time split, tool table, tokens, context growth,
  subagents) don't count Timeline as a 6th metric requiring new artifact fields — plan.md's T15
  column list reads as this task's own elaboration of a view built from the existing 5, not a
  separately-specified requirement. Concretely:
  - **"model/tools/user split for that turn"**: only the tools portion is exactly knowable
    (`ToolCall.durationMs` already carries `turnIndex`). Session-level model/user time comes from
    `time-split.ts`'s interval math over raw event timestamps, which the artifact never retains
    per-turn. Rather than fabricate a split with no real signal behind it, the Timeline shows the
    honestly-derivable "Tools time" column and a "Span" column (wall-clock gap to the next turn's
    start, or to session end for the last turn) — explicitly documented as a gap, not a
    processing-time claim, since it also folds in the user's idle time before their next prompt.
  - **"a short prompt preview"**: the artifact never retains user-prompt text anywhere (checked
    `SessionMeta`, `ContextPoint`, `ToolCall` — none carry it). The "Activity" column substitutes
    the distinct tool names called in that turn (e.g. `AskUserQuestion, mcp__claude-in-chrome…`),
    which is the closest honest stand-in for "what happened in this turn" the artifact supports.
  - Extending the schema to carry these (a proper per-turn `TurnStat[]` computed in a new
    `metrics/` function, plus prompt text captured in `build-model.ts`) would be a reasonable
    follow-up, but is a multi-layer change spanning `model/`, `metrics/`, and `artifact/` — well
    beyond this task's Files list — and is flagged here rather than done silently.
- `⏎`'s "expand the turn's events" (plan step 1) is implemented as a nav-stack screen defined
  inside `Timeline.tsx` itself (no separate file was allotted for it), listing every tool call and
  assistant-message token point for that turn in time order — reusing the same
  `NavScreen`/`nav.push` pattern T14 established, including `nav.selection` (not local `useState`)
  for the highlighted row, per the lesson T14 already recorded about screens losing local state
  across a push/pop round trip.
- Per plan.md's explicit note ("do not edit `App.tsx`"), the Timeline/Context tab registration
  side-effect imports were added to `cli/index.ts` (the composition root that already imports
  `App.tsx`), not `App.tsx` itself — `App.tsx` was not touched by this task. Import order there
  (`App.js` — which pulls in `Overview.js` — then `Timeline.js`, then `Context.js`) is what fixes
  the `⇥` cycle order to Overview → Timeline → Context, confirmed live above.
- Added `formatCount` to `format.ts` (T13's file, outside this task's Files list) for rendering
  raw token counts (`12.3k`, `1.2M`) — a small, additive, non-conflicting extension in the same
  spirit as T14's necessary touches to files outside its own list.
