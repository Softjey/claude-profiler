**Baseline:** `pnpm verify` → build clean, 15/15 tests pass (3 files: existing parse suite plus new `src/cli/resolve-session.test.ts` and `src/tui/SessionPicker.test.tsx`).

**Convention check:**
- Layer direction: `src/cli/resolve-session.ts` imports from `../parse/*` and, for the shared
  `SessionListing` type, from `../tui/SessionPicker.js` — matches `cli → tui → ... → parse`.
  `SessionPicker.tsx` imports nothing from `cli`. (Caught and fixed a violation during this
  verification pass: the type originally lived in `resolve-session.ts` and `SessionPicker.tsx`
  imported it back, which is backwards — moved the type's home to `tui`.)
- No new `Ms`/`At` fields introduced by this task.
- `resolveSession` never throws for a missing/unparseable transcript in the ambiguous branch —
  `parseTranscript` already degrades leniently; only a stream-level failure would reject, and
  none of the tested paths do.
- No label calls a derived duration "exact" — this task adds no duration metrics.

Notes:
- In a non-interactive/non-TTY invocation (`stdin.isTTY` false — e.g. piped or `/dev/null`),
  the ambiguous case falls back to printing the candidate list to stderr and exits 1, rather
  than crashing on Ink's raw-mode requirement. This isn't in plan.md's acceptance criteria but
  was necessary for `pnpm verify`/CI-style invocations not to blow up; the interactive picker
  itself was verified separately via a real pty.
- Turn count for the picker is computed directly from `parseTranscript` (T2), counting `user`
  records that are genuine prompts (not `isMeta`, not solely `tool_result` blocks) — the fuller
  `turnIndex` definition from T4 doesn't exist yet and T12 only depends on T1/T2, so this is a
  deliberately lighter, self-contained count for display purposes only.
- Added `ink-testing-library` as a devDependency to test `SessionPicker.tsx`; also widened
  `vitest.config.ts`'s include glob and `tsconfig.json`'s exclude to cover `.test.tsx`.
