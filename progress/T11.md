**Convention check:**
- Structure: new code lives in `src/artifact/` (`profile.ts`, `schema.ts`, `write.ts`) per the
  Structure convention.
- Dependency direction: `profile.ts` imports from `metrics/`, `model/`, `parse/`, and
  `hooks/sidecar.ts` (to merge exact timings per SPEC's `ToolStat.exactMs`/`approvalMs`).
  `hooks/` sits outside the stated `cli → tui → artifact → metrics → model → parse` chain and
  nothing in `hooks/` imports back from `artifact/`, so this stays one-directional. `cli/index.ts`
  now imports `artifact/profile.ts` and `artifact/write.ts`, consistent with `cli → ... → artifact`.
- Naming: every duration field ends in `Ms` (`spanMs`, `turnCount`/`messageCount` are counts, not
  durations, correctly unsuffixed); every timestamp field (`generatedAt`, `startedAt`, `endedAt`)
  ends in `At` and is ISO 8601 (`new Date(...).toISOString()`).
- Errors: `buildProfile`/`assertProfileInvariants` intentionally throw — this is the one
  user-facing "must not silently write a broken artifact" case the task calls for, not a
  parse-level problem; parse-level issues still only increment `diagnostics.skippedLines` /
  `diagnostics.unknownRecordTypes` (untouched, reused from T1's `parseTranscript`).
- Honesty rule: `timeline.precision` stays whatever `mergeSidecar` (T10) decided — "derived"
  unless a sidecar actually matched calls — and `ToolStat.exactMs`/`approvalMs` are passed through
  unmodified. No new label anywhere calls a derived number exact.

Notes: `SessionMeta.spanMs` is computed independently (min/max record timestamp) from
`timeline.spanMs` (computed from event/tool-use points in `time-split.ts`); the two are close but
not asserted equal — the acceptance criterion and FR9's invariant are about `timeline`'s own four
buckets summing to `timeline.spanMs`, which is what's enforced. `JSON Schema` in `schema.ts` is
hand-authored (no schema-generation library was in `package.json`'s deps) and kept in sync via
`profile.test.ts`'s structural-validation test rather than a build-time codegen step; flagged here
in case the user wants a generated schema instead in a follow-up.
