Notes (deviations / things worth knowing):
- **`tool.kind === "task"` does not reliably identify a subagent-spawning call.** Every real
  transcript found locally names this tool `"Agent"`, never `"Task"` (see
  `resolve-subagents.ts`'s own comment on this), and `classifyKind` (T6's `tool-stats.ts`, outside
  this task's Files list) only special-cases the literal name `"Task"`. `ToolDetailScreen` was
  first written gated on `tool.kind`, found broken against the real `6b30775a` session (`Agent`
  calls fell through to `CallDetail` instead of `SubagentDetail` despite `profile.subagents`
  correctly resolving them), and now matches directly on whether `profile.subagents` has an entry
  whose `parentToolCallId` equals the selected call's id — correct for `"Task"`, `"Agent"`, or any
  future name, with no dependency on `tool.kind` at all.
- **Selection had to move from local `useState` onto `nav.selection`/`nav.setSelection`
  (`shell.ts`, T13) in `Overview.tsx`, `ToolDetail.tsx`, and `SubagentDetail.tsx`.** Each nav-stack
  push/pop fully unmounts and remounts the screen at that tree position (a different component
  type replaces it, then is replaced back), so any "which row is highlighted" state kept in a
  screen's own `useState` was silently reset to its initial value on the way back — exactly the
  behavior the second acceptance criterion rules out. `shell.ts` already exposed
  `nav.selection`/`nav.setSelection` per frame for this; T13's `Overview.tsx` just wasn't using it
  yet, since T13 alone never pushed a second frame to expose the gap. Confirmed live on `54fd3ef0`
  (see above) after the fix.
- **Found and fixed a T13 latent bug while wiring the first real push**: `Overview.tsx` registered
  its tab as `registerTab({ id: "overview", render: OverviewScreen })` — passing the component
  function itself as `render`, rather than `(props) => <OverviewScreen {...props} />`. Since
  `nav.current.render(props)` calls `render` as a plain function, a bare component reference runs
  its hooks *inline on the caller's fiber* instead of mounting a proper child (invisible while
  Overview was the only screen ever rendered there). The instant T14 pushed a screen with a
  different hook shape on top of it, React threw "Rendered fewer hooks than expected" and the TUI
  went blank on the very first `⏎`. Fixed by wrapping the registration in `Overview.tsx`; also
  fixed the same pattern in `Overview.test.tsx`'s own test harness. `ToolDetail.tsx`/
  `CallDetail.tsx`/`SubagentDetail.tsx`'s `screen(...)` builders were written correctly (JSX-
  wrapped) from the start, so no other screen had this issue.
- `CallDetail`'s "full input" is `ToolCall.inputPreview`, which `tool-stats.ts` (T6, outside this
  task's Files list) already truncates to 200 chars at the metrics layer — the artifact does not
  retain anything beyond that. `CallDetail` renders it unclipped by table-column width (unlike
  `ToolTable`'s cramped column), i.e. "full" relative to what the Profile artifact carries, not
  literally the raw tool input.
- `ToolDetail.tsx` imports `CallDetail.js` and `SubagentDetail.js`, and `SubagentDetail.tsx`
  imports `ToolDetail.js` back (to let a subagent's own tool rows drill into the same
  `ToolDetail`) — a real mutual dependency, not a mistake. Static ESM imports handle this fine
  (Node/tsc's live-bindings resolve correctly since neither side calls the other at module-eval
  time, only from within event handlers after both modules have finished loading).
